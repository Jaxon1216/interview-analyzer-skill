## 本课重点

一次任务可执行多次，id 保持不变，attempts 在每次调用前增加。示例只有同步函数，没有外部消息队列。

## 主链与职责

Task 从 queued 开始。run_task 设置 running，增加 attempts，再把同一 id 传给 handle；成功设为 done 返回，ValueError 则设为 failed，循环判断是否仍有预算。

## 源码阅读

先看 [Task 与 run_task](../../task.py) 的字段和 while，再看 try/except/else 的分支。没有创建新任务的语句；其他异常不会被 ValueError 分支捕获。

## 机制与边界

### 有限重试

默认 max_attempts=2。第一次 ValueError 后 status 为 failed；下一次尝试前改为 running，attempts 增至 2。若成功则 done；若仍是 ValueError，次数耗尽后保持 failed 返回。两次 handle 接收到的 id 相同。没有退避等待、持久化、幂等或并发控制。

### 参数边界

max_attempts 小于 1 会直接抛出 ValueError，不执行 handle。已有 attempts 消耗同一预算；Task 对象不会在本函数内被重置。

## 需要懂什么

id 表示任务身份，attempts 表示已经尝试多少次；失败状态既可能在重试前短暂出现，也可能是预算用尽后的终态。相同 ID 不能避免 handle 产生重复副作用。

## 需要记住什么

queued → running → done，或 running → failed → running；耗尽后停在 failed。只有捕获的 ValueError 会进入重试分支。关联 [Q1](../任务样本/面经.md#q1-同一任务与多次尝试)。
