# HTML 教学品质修订

日期：2026-11-08。用户验收指出，上一轮 HTML 虽然事实和交互检查通过，仍缺少 teach 的教学精华。本轮因此重做教学设计、生成骨架与两张样课，并将教学审读从技术检查中分开。

## 已确认的根因

旧 C05 一次列出来源优先级、声明并集、None/空列表、注册表失败等六种答案；旧 C06 的共享场景停在第一个执行退出，没有操作到“最后一方退出后释放”的核心结局。两页有状态变化和源码证据，却缺少同一个实例逐步演进的路径。原有三栏与 radio 模板容易把状态枚举当作短课，原有验收也容易由事实、分支和截图通过推导教学合格。

本轮采用 teach 的单一学习成果、匹配已有知识、完整工作示例、即时解释反馈与按需参考。默认不引入强制猜测、答题、实验作业或可见预览。没有机械创建 MISSION 等整套教学工作区文件。

## 实际改动

- [HTML 教学规则](../../skill/project-interview-skill/references/rules/html-teaching.md)明确读者已知、唯一主要未知、具体成果、持续实例、最小条件变化、图形与反馈、迁移方法和三类验收。
- `assets/topic.html` 改为可扩展阅读骨架，不限定三栏、radio 或分支数量；将领域图形、动作与状态逻辑留给具体机制。同步 Skill、提示词、课程规则和本机安装副本。
- C06 用任务—占用连线—共享 client 图推进完整过程。两种顺序都可完成，并解释正常持有者提出释放请求、借用者仅归还占用的区别。提前释放作为明确的错误策略对照，可恢复后继续。
- C05 固定 A/B 声明与调用目标，读取 B 后仅切换 A 的来源；来源选择、声明集合与调用结果实时重算。完整路径、重复推演、原始错误及例外移到补充区，主图和原因保持直接可读。
- 浏览器测试按机制检查完整操作路径、保持其他条件的比较、因果结果、重置、键盘与打印；不要求页面为测试器继续套固定 radio。保留旧页面适配器用于兼容检查。
