# 简历 Bullet Few-shot（领域中立）

与[默认酥神模板](../excellent-resumes/susu-bullet-template.md)一起使用，只学习表达，不复制场景、数字或技术组合。目标模式可选仓库已有机制，贡献模式按用户说明限定参与范围。

## 从事实到成稿

先从完整材料识别核心职责和系统机制，查证协作关系后，围绕目标或工程问题组织支柱；不把材料的分组直接当标题或条数。成稿让读者看懂为什么需要该设计、怎样实现、具体改变什么；职责、协作与行为条件用于说明因果，不能代替设计动机。下列例子采用不同起笔与组织方式，不要求每条套 STAR。

工程目的可以依据当前机制解释，事故、历史演进和收益数字须另有来源。具体变化已写进动作或条件时不重复补收益句；指标缺口和测量计划放源码证据记录、相关面试回答或用户明确要求的验证材料。

## 技术栈摘要：核心组合与实现细节分工

**假设事实**：Python / FastAPI 服务通过 SQLAlchemy 访问 PostgreSQL，使用 Redis 与 Celery 执行后台任务；外部请求由 httpx 发起，配置由 pydantic-settings 读取。依赖材料同时列出了各库版本与 asyncio、logging 等标准库模块，技术名称均已核实。

**依赖盘点式反例**：Python 3.12、FastAPI 0.115、SQLAlchemy 2、PostgreSQL 16、Redis 7、Celery 5、httpx、pydantic-settings、asyncio、logging。

**技术栈摘要**：`Python + FastAPI + SQLAlchemy + PostgreSQL + Redis + Celery`。

httpx 发起外部请求的具体做法，属于相关机制条目；不必把每个依赖都列入摘要。压缩摘要不能抹去正文里的关键技术，也不能把本例组合迁移到没有这些实现的项目。此格式是新增输出项的示范，不是金样原文摘录。

## 选材示例：细节归入所服务的机制

**未分组的材料**：视频转码请求返回任务号；下载接口校验文件归属；编码器从队列取任务；进度与文件地址关联任务号；失败记录原因；相同输入和编码参数命中已有成功结果时直接复用。

可组织为“异步转码任务”和“转码结果复用”，不按提交、查询、下载、鉴权各写一条。队列、任务状态和产物交付共同说明异步任务如何完成；输入与参数的匹配条件说明什么情况下跳过编码。文件归属检查放在交付步骤，不能取代转码主线。最终条数由机制决定。

## 正例：机制起笔，动机融入做法

**事实**：错误处理入口统一，按错误类别选择有限重试、降级或快速失败；没有旧实现证据与线上指标。

> - **分层容错：** 将错误处理集中到统一入口，按错误类型选择有限重试、降级或快速失败；为避免重试产生重复副作用，仅对幂等操作重试，各分支统一返回处理结果，调用方无需分别判断底层异常。

机制起笔仍交代为什么限制重试，以及调用方看到什么变化。不为补背景编造“过去逻辑散落”，也不用待测尾注代替效果。

## 正例：真实演进起笔

**事实**：旧流程中能力固定，新版通过统一接口和独立扩展点接入；核心调度保持不变。

> - **可扩展编排：** 为支持固定流程之外的能力接入，将处理步骤改为统一接口下的能力编排，差异实现放入独立扩展点；新增实现通过扩展点接入，无需修改核心调度。

旧→新有依据才写。约束与运行机制相关，结果是具体结构变化。

## 正例：复杂机制分层

**事实**：系统维护预算内的运行上下文，并保存可恢复快照。

> - **上下文与断点恢复：** 为控制输入规模并保留中断后的恢复进度，将活跃上下文与持久化运行状态分开维护。
>   - 按预算保留任务约束与最近结果，较早记录压缩后回填，控制下一轮输入规模。
>   - 每轮保存状态快照，中断后恢复最近进度，已完成步骤无需重新执行。

一级说明需要兼顾的目标，二级分别解释关键做法与变化。不强迫每个子机制重复背景。

## 反例与改写

```text
- 接入缓存和重试，优化接口请求。
- 针对接口可靠性不足的问题，建设请求可靠性治理体系，提升稳定性，收益待测。
- 异步落库：完成订单保存；未来增加死信、补偿和唯一索引。
```

第一条没有解释怎么工作，第二条用大词与待测尾注掩盖机制，第三条混入未来计划。

若事实支持请求超时、幂等重试和快速失败，可改成：

> - **超时与有限重试：** 为下游请求设置超时，仅对幂等操作按退避策略有限重试；非幂等操作与次数耗尽的请求直接失败，避免重复副作用和持续占用请求资源。

这里只示范表达，不能据此宣称任意项目都有这些机制。

## 同一事实：从流程说明改成有因果的 bullet

**事实**：报表提交接口保存任务与输入后返回任务 ID 和受理状态，队列消费者生成报表并保存结果；可按任务 ID 查询状态及下载产物。没有耗时测量、旧版记录或历史事故材料。

**只有流程，仍需改写**：

> - **异步报表：** 保存任务和输入，返回任务 ID；消费者生成报表并写结果，查询和下载接口按任务 ID 读取数据。

**连起目标、做法与变化**：

> - **异步报表：** 为将报表提交与生成分开，接口保存任务后即返回受理结果，由队列消费者在后台生成报表；用户可凭任务 ID 查询状态并下载产物，提交请求无需等待生成完成。

后者说明异步设计服务什么使用需求，并落到提交方看到的行为。无需虚构“旧版频繁超时”，也不能把受理响应写成生成速度提升。这里的目的来自当前接口与执行边界分析，事实记录中说明该依据即可。

## 目标、指标与历史边界

**假设材料**：运营人员提交批量任务，源码有队列受理、状态查询和结果下载；没有线上收益和旧版本记录。三个功能可以归在“批量任务处理”支柱下，目标是让用户提交后能够跟踪处理状态并取得结果。成稿保留这个目的与对应能力，不把目标改写成未经证明的“节省 80% 人力”。

> - **批量任务处理：** 面向批量任务提交后的状态跟踪与产物获取，提交时生成任务标识并入队，后台消费者执行处理；查询和下载关联同一任务，用户可凭任务标识查看状态并获取产物。

若材料只有“改前 10 并发均值 1000ms、改后单并发 P95 200ms”，不能写“延迟下降 80%”；分别记录环境与统计口径，正文可只写机制。若只有当前队列实现，口播可说“现在回看，同步处理会占用请求资源”，不能说“我当时对比两种方案，分两阶段完成改造”。真实历史另有用户陈述或版本证据时，再据此写演进。

## 技术术语取舍示例

按[技术术语选择](../rules/oral-and-resume-patterns.md#技术术语选择)比较目标岗位下的中英文表达。下面的说明用于生成者分析，不附在简历正文。

**假设事实**：Go 服务以 `context.Context` 传递取消信号，通过 `http.NewRequestWithContext` 发起外部模型请求；没有延迟指标，也不清楚对方是否停止计算。

**过度泛化**：传递上下文并控制外部请求，避免持续等待。

> - **Go Context 取消传播：** 为让外部模型调用跟随请求取消结束等待，将 `context.Context` 传入 `http.NewRequestWithContext`，取消时中断本地 HTTP 请求。

名称说明了实际取消链路，正文解释其本地作用；不能据此宣称远端模型必定停止计算，也不必把每个辅助函数都写入简历。这里的标准库 API 是给定事实，不能迁移到未知语言或未知实现中。

**假设事实**：面向前端岗位，后台任务执行期间，服务端通过 SSE 推送进度事件，客户端据此更新进度。

> - **SSE 任务进度推送：** 面向后台任务的进度展示，通过 SSE 接收服务端进度事件并更新页面，让用户在任务执行期间获知处理进展。

SSE 点明协议，正文交代使用需求、双方做法及用户看到的变化，不补“提升体验”复述前文。这是局部机制的写法，是否值得成为一级支柱还须看完整项目；不能继承重连、回放、取消轮询或延迟收益。

**假设事实**：面向后端岗位，写入时按业务唯一编号复用已保存结果，不重复执行同一操作。

> - **请求幂等：** 按业务唯一编号关联处理结果，重复请求返回已保存结果，避免同一操作被重复执行。

“幂等”在该语境清楚自然，无需为了英文数量改成 Idempotency，零英文也合格。标题中的中英文选择不改变事实、职责或结果边界。

**不合适的表达**：将私有类 `FlowKernelX` 写成架构名称；把“幂等、限流、事务”堆成 `Idempotency + Rate Limiting + Transaction`；只有模型调用却命名为 `RAG Agent Harness`。前者没有同行通用性，后两者分别缺少表达优势或实现支持。这些反例不建立特定词的永久禁用表。

## 成稿检查

- 每条一级 bullet 以 `- **具体支柱名：** 正文` 独立成行，标题是具体工程机制，私有类名/函数名与文件路径留在证据索引。
- 整组抓住项目核心职责，每条围绕同一目标或工程问题连起动机、做法与变化；保留关键实现，不机械填四槽或强行补收益。
- 不了解源码的读者能复述为什么需要该设计，不能只复述调用步骤；工程目的与风险分析不冒充历史事故，各条不反复套“针对……的问题”。
- 信息多时按子机制拆二级，不堆全栈名词、无关数字或整条源码调用链。
- 没有“提升性能/优化体验”一类空泛结果，没有待测尾注或未来计划；真实数字须有来源。
- 当前缺口使某项效果不成立时缩小主张；不得把局部原子性写成端到端保证。
- 每条都能引出关于动机、权衡、边界或运行方式的自然主问。
- 没有复制金样的项目事实、指标与身份。
- 技术名称与事实匹配并参与机制解释；通用概念采用目标岗位熟悉的叫法，具体框架与库可说明用途，不因知名度或中文替代词而抹去关键技术。没有固定英文数量、装饰性名词或正文中的逐词选择说明。
