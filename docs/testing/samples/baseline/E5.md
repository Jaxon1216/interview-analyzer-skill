# 内部批量报表模块

> 本文仅整理用户明确陈述的本人贡献与版本经历；材料为本用例假设，无可访问源码或 PR，与 DeerFlow 无关。

## 简历 bullet

- **批量报表异步化：** 负责内部批量报表模块，第一版在 HTTP 请求内生成报表，验收中长任务触发网关超时；比较延长超时与队列两种方案后，第二版将生成移至后台队列，以任务 ID 串联状态查询和结果下载，验收确认请求返回受理状态、报表在后台生成。

## 方案口播

**面试官问题**：为什么从同步报表改成队列方案？两版之间具体改变了什么？

**口播版**：我负责内部批量报表模块。第一版在 HTTP 请求里生成报表，验收发现长任务触发网关超时；它暴露的是报表执行时长与请求等待期限绑在一起的问题。我当时比较过延长网关超时和改成队列：延长超时可以放宽等待窗口，但报表仍占着请求，长任务继续依赖网关期限；队列则把请求受理与后台生成拆开，但需要让调用方能查询状态和下载结果。第二版我采用队列，通过任务 ID 关联状态查询与下载。验收确认请求先返回受理状态，报表在后台生成；受理不等于报表已经完成。这一结果可以说明请求生命周期与生成过程分离，没有性能数字，所以我不把它表达为耗时降幅或吞吐提升。版本和选型过程依据是我提供的经历陈述，当前没有仓库或 PR 进一步核验。
