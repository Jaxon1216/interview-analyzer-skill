# GenBI｜后端研发目标简历

> 以下为目标简历与学习口播，供掌握后选用。分析范围为 GenBI 完整 Go 后端；前端仅用于核对 HTTP 与事件通知契约。

## 项目简介

GenBI 是基于 Go、Gin 与 GORM 的智能 BI 后端，用户上传 XLSX/CSV 并指定分析目标、图表类型后，由 DeepSeek 生成 ECharts 配置及分析结论。系统使用 MySQL 持久化图表与任务状态，支持同步生成、RabbitMQ 异步生成和 SSE 终态通知。

## 简历 bullet

- **模型输入与结果归一化：** 为让不同上传格式与模型返回满足统一的结果契约，将 XLSX 首个工作表转为 CSV，并兼容原始 CSV 输入；按分析目标、图表类型组织提示，解析配置与分析结论，对配置执行 JSON 清洗、非法内容回退为空对象，使同步与异步链路以相同字段保存图表结果。
- **异步生成与事务消息表：** 将图表提交与模型执行分开，HTTP 受理后返回图表 ID，由独立消费者生成并落库，调用方可按 ID 查询状态与结果，提交请求无需等待生成完成。
  - 为让任务记录与投递意图一起提交，使用同一 MySQL 事务保存等待态图表与待发送消息；后台批量扫描事务消息表并投递 RabbitMQ，发送失败保留待发送状态、累加重试次数，供后续轮次继续投递。
- **状态 CAS 幂等消费：** 面对事务消息补发可能产生的重复投递，以等待态到运行态的条件更新争抢任务执行权，只有更新命中的消费者进入模型调用；未命中时直接确认消息，跳过生成、失败回写与状态事件，避免重复消息再次调用模型或覆盖已有任务状态。
- **生成限流与调用取消：** 为约束模型调用频率和等待耗时，同步、异步生成共用按用户划分的 Redis 限流额度，使用每秒 3 次的配置，在调用模型前拒绝超额请求；将上下文传递到外部 HTTP 请求，异步调用使用可配置超时，同步调用跟随请求上下文，使模型请求可随超时或请求取消结束等待。
- **跨进程终态通知：** 为让调用方获知独立消费者的处理终态，消费者经 Redis Pub/Sub 发布图表 ID 与成功、失败状态，HTTP 服务通过 SSE 转发匹配图表的事件；订阅前校验登录身份与图表归属，终态后结束流、断连后释放订阅。发布通知出错仅记录日志，消息消费的确认流程继续执行。
