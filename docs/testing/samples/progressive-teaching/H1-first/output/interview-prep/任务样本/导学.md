## 学习目标与项目地图

任务样本把任务标识、状态、累计尝试次数和结果放在一个对象中，由同步执行函数调用外部提供的处理函数。正常返回时保存结果并结束；处理函数抛出指定异常时，执行函数根据剩余次数决定是否再次调用。它用于教学，没有 HTTP 服务、消息代理、存储、后台线程或部署配置。源码第一行也明确说明同步、无代理、无持久化、无退避。

这里的工程目标是从当前实现分析得到的：把“执行什么”和“何时重试、如何记录状态”分开，限制一次对象生命周期内按现有计数继续执行的次数。没有团队目标、真实上线经历或性能指标材料。

| 组件 | 职责 | 阅读入口 |
| --- | --- | --- |
| 任务数据对象 | 保存任务标识、状态、累计次数、结果；数据在进程内，由调用者和执行函数共享 | [task.py](../../../project/task.py) 的 `Task`，第 6～11 行 |
| 同步执行函数 | 校验次数参数，控制循环，更新状态和次数，选择成功返回或失败后继续 | [task.py](../../../project/task.py) 的 `run_task`，第 14～27 行 |
| 外部处理函数 | 接收任务标识，返回字符串或抛出异常；具体业务实现不在本项目中 | `run_task` 的 `handle` 参数，第 14、21 行 |

代表性链路有三条：

1. 新任务 → 次数参数合法 → 进入循环并记一次尝试 → 同步调用处理函数 → 保存返回值 → 标记完成 → 返回原任务对象。见 [C01](../guide-backend/01-同步执行与任务状态.md)。
2. 新任务 → 处理函数第一次抛出 `ValueError` → 标记失败 → 仍有次数则回到运行态 → 第二次正常返回 → 标记完成。见 [C02](../guide-backend/02-有限重试与异常边界.md)。
3. 处理函数持续抛出 `ValueError` → 次数用完后返回失败对象；若抛出其他异常则立即向调用者传播。见 [C02](../guide-backend/02-有限重试与异常边界.md)。

## 选读与进阶目标

当前核心范围已经覆盖全部源码机制。以下是触发条件明确时才值得展开的增强，不属于已实现能力，也没有生成空白课程。

- 处理函数包含扣款、写库等不可重复副作用时，需要幂等设计。任务标识能作为设计输入，但当前没有去重记录或唯一约束。入口：[C02 的副作用边界](../guide-backend/02-有限重试与异常边界.md#机制与边界)。
- 下游故障可能持续或处理函数可能长时间不返回时，需要结合错误分类考虑退避、超时和取消；当前只限制调用次数。入口：[C02](../guide-backend/02-有限重试与异常边界.md)。
- 多进程共享任务或进程重启恢复成为需求后，才讨论持久化、任务领取和并发控制；当前状态仅保存在一个 Python 对象中。入口：[C01](../guide-backend/01-同步执行与任务状态.md)。

## 学习重点与记忆提纲

先理解对象归属：调用者传入任务，执行函数修改它，处理函数只接收标识。再理解顺序：进入一次尝试前先设置运行态并加次数；正常返回才写结果并标记完成。读 [C01](../guide-backend/01-同步执行与任务状态.md) 后可进入 [Q1](面经.md#q1-同步执行如何记录状态并交付结果)。

随后理解次数与终止的因果：循环看的是任务对象已有次数与总上限的比较，默认上限二包含首次调用；失败态不一定是整次执行的终点。读 [C02](../guide-backend/02-有限重试与异常边界.md) 后可进入 [Q2](面经.md#q2-有限重试如何决定继续与停止)。

需要记住三个限制：只捕获 `ValueError`；状态不会阻止完成任务再次执行；次数限制不提供超时、幂等或重启恢复。状态字符串是记录，不是受约束的状态机。
