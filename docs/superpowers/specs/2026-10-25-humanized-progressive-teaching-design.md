# 自然表达与渐进式 HTML 教学：设计提案

日期：2026-10-25。仓库基线：`106ea5f`（1.4.2）。状态：用户已确认按推荐方案实施；以下为本次实现与验收依据。

## 目标与已有约束

本次优化有两个落点：让生成过程与材料的表达自然、具体；让使用者读到某一课时，可以把该课或其中一个难点展开为独立 HTML 教学页。

保留现有默认交付：第一次生成 `导学.md`、`面经.md` 和全部核心 Markdown 课程。核心课程本身讲完整，HTML 是后续按需增加的讲解形式。方向、输出路径、B/Q/C 编号、目标简历/实际贡献模式以及用户笔记的处理沿用现有契约。

上游来源：

- [blader/humanizer v3.1.0](https://github.com/blader/humanizer/blob/d4b81278e6604e237bf32f0f7ce5c217aee94269/SKILL.md)：适配其自然表达与事实守恒方法，固定到 `d4b81278e6604e237bf32f0f7ce5c217aee94269`。
- [mattpocock/skills 的 teach](https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/productivity/teach/SKILL.md)：用户提到的 `/tech` 对应这里的 `/teach`。适配其教学方法与 HTML 呈现方式。

两者均为 MIT：Humanizer 的版权声明为 `Copyright (c) 2025 Siqi Chen`，teach 为 `Copyright (c) 2026 Matt Pocock`。实现时在适配参考文件内记录具体来源、版本及改编范围，并把许可全文放入 Bundle 的 `references/upstream/`。安装后的 Bundle 自包含，不在每次生成时下载上游。

teach 提供的是教学行为与 Markdown 格式规范，没有附带现成的 HTML 模板、CSS 或模拟器。本方案的页面与交互由现有 Agent 按选定课程生成。

## 方案选择

推荐在现有 `project-interview-skill` 内增加 HTML 深化模式，把两类方法适配进 references。原来的入口和安装方式可以继续使用，生成过程只读取当前阶段需要的规则。

另外两个方案暂不采用：分别安装两个上游 Skill 会增加环境依赖，还需要处理规则冲突；首次批量生成全部 HTML 会增加首轮成本，也难以围绕学习者当下不懂的机制调整讲解。

## 表达规则如何进入流程

新增 `references/rules/writing-style.md`，承载适合中文工程材料的 Humanizer 规则与少量改写示例。主 `SKILL.md` 保留简短共同约束，并明确在撰写回复、导学、课程、简历口播和 HTML 文案前读取该参考。

表达时直接说机制和结果，删除空泛重要性、铺垫、重复总结、机械排比和装饰性术语。允许有信息的技术比较，保留因果、边界与岗位常用术语；自然表达不等于把复杂机制压缩成口号。

润色在内容形成之后做，并复核事实：不改动指标口径、条件、责任范围、来源、代码、符号、链接目标和 B/Q/C 编号。不为增加人味编造经历、事故、情绪或实验结果。保留既有目标模式允许的第一人称学习口播，不把它改成真实履历证明。

Humanizer 的去加粗、去列表、去箭头和压缩背景建议不能破坏本项目的 bullet 格式、课程导航、流程图和必要教学解释。标题、关联表等结构以现有交付契约为准；“尚未实测”“如果重新设计”等证据限定不得作为套话删除。

默认只交付成稿，不额外输出上游式的初稿、人工感审计和第二稿。只有用户明确要求润色过程时才展示。

## 两个模式与触发条件

1. **默认资料生成/更新**：执行当前完整 Markdown 交付，课程末尾增加按需学习入口；不自动生成 HTML，不创建空 HTML 文件或尚不存在的文件链接。
2. **HTML 深化**：用户明确要求 HTML、交互讲解，或使用课程末尾的提示词时进入。按当前项目与方向解析课程路径和 C 编号；也接受指定 Markdown 文档及其小节。只处理选定范围，不重新生成整套资料。

指定一课且范围清楚时直接生成。只给 C03、而当前目录有多个项目或方向时，再询问所属材料；不通过猜测覆盖某一套课程。未要求 HTML 的普通追问仍直接在对话回答。

在现有“生成顺序”之前判断模式。HTML 请求可直接从已有文档开始，不重新要求项目描述、不重跑全部 B → Q → C 生成。Skill 的描述元数据补充 HTML 深化的触发范围，但不承诺安装后会出现独立的 `/teach` 或 `/tech` 命令；两者在这里属于方法来源。

## 在 Markdown 中留下可以跨聊天使用的入口

每份课程末尾增加“按需生成 HTML 讲解”，给出一段可复制提示词。提示词填写实际项目标识、从项目根目录定位的 Markdown 路径、C 编号、范围和基线；同一个代码块不混用两种路径起点。

生成器把当前文件的真实信息写进提示词，不要求读者手动寻找技能安装路径，也不依赖之前聊天里出现过的事实。正文保留简短说明：复制到能够访问同一项目的 Agent 中，可以追加自己不懂的点。

每课导航区记录或链接可定位的源码基线。用户不追加难点时，提示词默认解释整课；具体目标已清楚时不启动额外访谈。

下面是示意交互，实施时替换为该项目的真实课程信息：

```text
使用 project-interview-skill 的 HTML 深化模式。
项目：当前仓库；方向：后端。
课程：C03；文件（相对项目根）：interview-prep/guide-backend/03-任务状态流转.md。
范围：本课“机制与边界”。请生成独立 HTML 教学页。
源码基线：本课程文首记录的版本；如当前仓库不同，先核对与本节相关的变化。
先读取课程、它链接的导学与相关面经，以及讲解所需的源码；核对课程记录的源码基线。
保留当前实现、分析推断和演进方案的边界，保留原文与笔记。
我不懂的点：状态变化如何与任务重试对应。
```

主导学说明使用方法，并通过已有课程导航引导选课。面经允许按 Q 编号或小节选择讲解范围，复用关联课程提供机制依据，不默认把整份面经做成巨型页面。

## HTML 深化的输入、内容与产物

新增 `references/rules/interactive-teaching.md`，仅在 HTML 模式读取。按以下信息组织讲解：选中 Markdown 的学习目标与难点、关联 C/B/Q、必要前置知识、实际源码与当前基线、用户追加的不理解之处。

先核对材料中的关键主张。源码与课程不一致时，把差异落到具体机制，基于实际可核验范围说明本页采用的基线；不擅自重写整套旧材料。源码无法访问时，仍可根据现有文档讲解，并明确未重新核验的范围，不伪造最新源码与测试结果。

页面围绕一个场景展开：具体输入或用户操作、状态/数据如何变化、关键代码为何产生这种行为、正常路径与异常边界、与相关面试题的连接。默认完整呈现答案，支持步骤切换、状态轨迹、图解与代码注释；交互用于解释机制，不用强制测验解锁正文。

教学图与模拟必须符合源码。简化模型和演进方案明确标注；模拟结果不能写成项目实测。只有用户要求练习、验证或测验时才加入相应环节。

默认输出到所选课程所在目录的 `html/`，文件名沿用课程或文档名；指定小节时追加可识别的小节名。同一输入先查原 Markdown 中已登记的 HTML 入口，沿用该路径；未登记时按文档名与小节名命名，遇到其他范围的同名页面则加后缀。重复请求只更新对应页面和入口，不删除其他 HTML。

页面身份以来源 Markdown 路径、C/Q 编号和所选完整标题层级确定；已登记路径优先于重新从标题推导名字。新文件名去除跨平台非法字符，冲突时使用由来源与范围产生的短稳定后缀，不因同名小节覆盖其他页面。

Markdown 是教学内容的依据，HTML 是它的派生产物。已有 HTML 含用户笔记或手工补充时先保留这些内容；无法安全合并时输出新的页面并说明位置，不能静默覆盖。HTML 中的导航、必要片段与交互不要求读者运行项目或安装依赖。

页面是无需构建的单文件 HTML，内联 CSS/JS，默认不加载 CDN、远程字体和运行时依赖。含中文语言标记、移动端布局、键盘可操作控件、必要的图示文字说明与减少动画支持。源码片段按文本转义，不能作为 HTML 执行。

页内标明课程、范围、源码基线与来源，提供返回 Markdown 和相关课程/面经的正确相对链接。HTML 可独立阅读；返回本地源码和 Markdown 的链接在保留目录结构时使用。若脱离项目分享，讲解与必要代码片段仍然可读。

只有 HTML 成功落盘并通过检查后，才在原 Markdown 的学习入口中登记可点击链接；保留提示词、用户笔记与既有链接，不自动标记“已学会”。生成 HTML 的提示词入口不承诺一个浏览器按钮能直接调用本地 Agent。

入口登记集中放在文档尾部的 HTML 区域；不往“简历 → 面试展开”的核心课程列或 Q 元数据“学习入口”混入 HTML，保留这些字段现有的 Markdown 课程链接契约。

## 最小修改范围

- `skill/project-interview-skill/SKILL.md`：共同表达约束、阶段读取规则、默认与 HTML 模式路由、增量交付规则。
- `references/rules/writing-style.md`：Humanizer 的中文工程适配、事实复核、来源与许可。
- `references/rules/interactive-teaching.md`：按需 HTML 的教学组织、输入核对、产物与检查、来源与许可。
- `references/rules/course-design.md` 与 `references/templates/output-templates.md`：课程学习入口、源码基线和 HTML 回链约定。
- `scripts/build_prompt.py`：同步默认模式的表达与后续 HTML 入口要求，避免辅助提示词仍指向旧行为；本轮不把它扩展成新的 HTML CLI。
- `README.md`、`README_EN.md`：首轮完整 Markdown、后续指定课程生成 HTML 的实际用法。
- `references/upstream/`：两份上游 MIT 许可及来源信息，仅用于溯源，不作为每次生成必须加载的提示词。
- `bin/project-interview-skill.js`：补齐 VS Code 安装的支持文件。当前该分支只写一份 instructions 文件，没有复制它引用的 references/scripts；实现时将完整 Bundle 放在该 instructions 文件旁的 `project-interview-skill/`，instructions 引导读取同目录 Bundle 的 `SKILL.md`，并按同一规则处理用户级与项目级安装。
- `tests/`：补充模式、表达与渐进式生成的行为用例；按需要扩展已有结构检查，不用关键词检查代替教学质量审读。

现有 npm 发布清单与通用 Agent、Codex、Claude、Cursor、Trae 的安装器已经递归包含 references，优先沿用；VS Code 的缺口按上条修复。不增加只在开发环境可用的外部 Skill 依赖。

## 验收与边界

1. 默认请求仍首次生成全部核心 Markdown 课，新增学习入口，不提前生成全部 HTML。
2. 新聊天只拿到入口提示词、安装后的 Bundle 与同一项目，即可定位选课和范围；歧义会集中澄清。
3. 请求 C03 的某一小节，只生成对应页面并添加有效链接；C01/C02 和用户笔记不被重写。
4. 重复生成、中文路径、多项目/多方向、源码漂移和仅有描述时，均保留正确范围、编号和证据边界。
5. 润色后机制、条件、数字口径、责任范围、链接与代码不变；文字更自然且必要解释完整。
6. HTML 可离线打开，导航与控件可用；无默认测验门槛、无执行代码伪装成演示、无未执行验证声称通过。
7. 在临时目录实际安装 Bundle，检查 VS Code 与默认安装后的引用和支持文件；运行 `npm test`、`npm run pack:check` 和 `git diff --check`。对真实生成的 HTML 做本地依赖与链接检查，并在浏览器检查离线打开、正文、导航、键盘操作、移动端和交互分支。保存行为首稿与审读记录，分别报告结构、语义与页面验证结果。

当前结构校验只会确认 Markdown 里的 HTML 文件链接存在，不能证明 HTML 内部链接、离线依赖或交互正确。本轮先明确要求 Agent 对单页逐项检查：通过 `file://` 打开，检查控制台、网络依赖、桌面与窄屏、每类控件、键盘遍历及返回链接；无法进行的检查如实列出。不把它描述为现有自动校验器已具备的能力，也不要求为校验单页而重新生成整套面经与导学。

本轮不增加全局学习档案、独立课程平台、强制登录、自动学习进度判断或批量 HTML 预生成。后续若需要跨课诊断、学习记录与课程计划，再基于实际使用扩展。
