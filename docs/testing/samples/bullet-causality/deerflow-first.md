# DeerFlow｜AI Agent 后端研发

> 以下为目标简历与学习口播素材，供掌握后选用。分析范围为完整项目，侧重后端核心机制。

## 项目简介

DeerFlow 是基于 Python、LangChain/LangGraph 与 FastAPI 的通用 Agent Harness，面向研究、代码执行与文件交付场景，协调主 Agent、子 Agent、工具和沙箱完成多步骤任务。配套 Next.js 对话工作台，支持 Skill/MCP 能力扩展、长上下文摘要、线程状态持久化与任务进度流式输出。

## 简历 bullet

- **中间件编排与扩展点：** 为分别扩展模型请求、上下文加工和工具执行，将运行能力组织为生命周期中间件；主、子 Agent 复用基础链，摘要、工具策略等能力通过独立钩子接入，扩展中间件在完整链组装后按锚点插入并校验顺序，使横切能力可通过扩展点参与推理与执行。

- **Skill 与 MCP 渐进发现：** 为控制能力目录扩展后每次模型请求携带的说明与工具定义，提供按需发现和激活机制。
  - 启用延迟发现时，Skill 先注入名称索引，再按需查询元数据、读取正文；MCP 工具经检索或路由命中后才向模型暴露完整定义，未激活的工具调用在执行入口被拦截。
  - 已加载 Skill 声明工具范围时，同时过滤模型可见工具、发现结果与实际调用，使能力发现仍受当前 Skill 的执行策略约束。

- **多 Agent 委派与容量控制：** 面向可拆分的复杂任务，主 Agent 委派专门子任务，子 Agent 使用独立消息状态、按需继承父会话快照，执行结果与进度由后端汇集，模型无需自行轮询。
  - 通过单轮委派数和单次运行总额度限制任务展开，再以共享运行槽和有界等待队列约束实际执行容量；队满或等待超时明确返回失败，防止多会话持续委派耗尽执行资源。

- **长上下文与断点恢复：** 长任务既要控制模型输入规模，又要保留可继续执行的状态，将活跃消息与持久上下文分开维护。
  - 按配置阈值生成摘要，成功后才替换旧消息，并保留近期消息与当前用户请求；摘要、委派账本和 Skill 引用独立进入线程状态，后续请求重新注入，压缩后仍可看到任务进展与已加载能力。
  - 提供 SQLite/PostgreSQL checkpoint 保存主 Agent 线程状态，中断后可显式恢复对话状态与执行中断点，避免仅依赖客户端重新拼接会话。

- **线程沙箱与执行租约：** 主、子 Agent 需要共享工作文件，同时保留用户和会话边界；通过统一沙箱接口执行命令与文件操作，按用户、线程映射工作区、上传与产物目录。并发执行各自持有沙箱租约，回收请求等待最后一个持有者释放后再交还 Provider，防止单个任务结束时提前回收仍被其他任务使用的环境。

- **长任务受理与流式重连：** 将 Agent 后台运行与 SSE 订阅分开，使长任务可按断连策略继续执行，并支持连接重试后的状态衔接。
  - 携带幂等键的相同请求复用已受理运行，请求内容冲突返回冲突响应；SQL 部分唯一索引限制同一线程同时存在一个待执行或执行中的运行，约束并发提交对线程状态的争用。
  - SSE 按事件 ID 推送进度，在保留窗口内依据 Last-Event-ID 回放；超出回放范围显式返回缺口并要求重载持久状态，避免把不完整事件流当成完整结果。
