# EdgeMetric｜存储引擎研发岗位

> 以下为目标简历与学习口播，供掌握后选用；分析范围仅为本次提供的合成项目描述。

## 项目简介

EdgeMetric 是运行在单机边缘设备上的嵌入式时间序列存储，支持按序列和时间范围写入、查询及删除。采用日志、内存有序表与有序不可变文件组织数据，通过序号控制查询可见性，并在后台落盘与文件合并期间保留活跃查询需要的数据。

## 简历 bullet

- **WAL 与尾部恢复：** 为使写入确认具有持久化依据，写入请求经单写入者队列串行处理，日志追加并 fsync 成功后才确认写入，再更新内存有序表；每条日志携带长度、校验和与递增序号，启动时重放日志，遇到不完整或校验失败的尾记录即停止，以有效日志前缀恢复数据。
- **内存表冻结与落盘交接：** 为限制单张内存表规模并在落盘期间承接新写入，内存表达到配置上限后冻结，新写入转入新表，由后台将冻结表写成有序不可变文件；原子替换 manifest 后才回收相应日志，使日志回收以新文件集合已发布为前提。
- **序号快照与多版本查询：** 为使一次查询在持续写入和文件切换期间保持固定的可见边界，查询开始时固定可见序号与文件集合，合并内存表及文件中的记录；同一键只取可见序号内的最新值，并由删除标记遮蔽较旧值，后续写入的版本不进入本次查询结果。
- **合并与延迟回收：** 为避免后台整理数据时提前淘汰活跃查询仍需读取的内容，文件合并保留这些查询可能看到的版本，旧文件在不再被查询引用后才删除，使查询能够继续使用开始时固定的文件集合。
- **序列与时间范围裁剪：** 面向按序列和时间范围读取的需求，利用文件的序列目录与时间范围排除不相关文件，再扫描候选记录完成查询，将记录扫描限定在候选文件内。
