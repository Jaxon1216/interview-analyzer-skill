## DeerFlow 与金样的逐项比较

- 整组选材：补稿从完整项目职责地图选出委派、模型/工具执行层、技能、上下文/记忆、线程资源及运行/事件状态。相较旧 T6，委派和上下文主线进入正文，产物读取下沉到工作区；没有把五类局部事实当固定支柱，也没有复制金样的四个标题。
- 标题：受限委派、中间件链、渐进加载、上下文压缩、执行租约、SSE 恢复均能识别正文的设计。英文保留 LangGraph、Agent Harness、Lead Agent、Skill、SSE、task、read_file、allowed-tools 等有机制作用的名称；没有用译名存在与否决定删词，也没有英文配额。
- 机制和约束：委派账本约束跨轮总额；输出净化/预算与句柄还原/授权的顺序；摘要成功才替换历史；最后持有者释放共享客户端；创建和只读订阅断开语义分别说明。接口和身份校验服务于这些机制。
- 具体作用：总额约束防止多轮绕过，独立执行 ID 防止同名调用覆盖，租约避免提前关闭共享客户端，gap 重载恢复视图；都可落到源码，没有量化收益、升级历史或 owner 身份。
- 初稿仍有重复机制和抽象尾句，已在修订稿删改。修订稿的多层 bullet 比截图原文更长，适合完整候选材料；实际一页简历还应按具体 JD 取舍，本次没有用字数冒充质量分。
- 可追问：可自然追问委派账本为什么按 run 计数、工具调用 ID 为什么不作执行所有权键、摘要失败怎样处理、共享沙箱什么时候释放、SSE gap 为什么恢复状态而非补齐事件。

## EdgeMetric 可迁移性审读

四条从日志持久化、内存表到文件转换、版本可见性/回收、文件裁剪组织。没有 Agent、Skill、上下文工程或金样技术组合。WAL 对应日志先持久化，MVCC 对应可见序号和版本保留；不将查询快照扩大为多键事务或串行化。刷盘提交只描述 manifest 替换后的日志回收次序，没有补造数据文件/目录同步证明。文件裁剪明确候选记录仍扫描。

正文均有实际条件，B3 用二级展开版本选择与后台回收；B4 简短直接结束，没有为了补收益编造扫描倍数。主 agent 本次未发现需要修订的缺陷，保留独立 first.md，不伪造 revised.md。
