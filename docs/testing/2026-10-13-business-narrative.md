# 业务主线改造与验证记录

日期：2026-10-13。范围：业务目标选材、指标口径与归属、历史决策来源。保留默认目标简历模式、具体机制写法、完整核心课程和 B/Q/C 关联。

## 改造

- 在仓库探索事实卡中加入服务对象、目标、障碍与结果维度；同一问题下的功能合并成支柱。
- 实现、责任、结果分别归档；责任仅在实际贡献模式限制入选。记录指标基线、统计对象、窗口、环境、来源和归属，不跨口径计算收益。
- 当前实现、真实历史演进、事后方案分析分别表达。用户明确陈述可以支持历史，不强制审计作者。
- 同步 Skill 入口、表达规则、口播契约、输出骨架、few-shot 和提示词脚本；运行时交付格式及结构校验器保持兼容。
- 实仓验证发现 macOS 路径别名导致相对链接错位，补充课程规则：先解析两端真实路径，移动产物后重新计算链接。

参考了 [bullet-okr-skills](https://github.com/yangjj-iso/bullet-okr-skills) 的目标组织与证据分层思路，按本项目的学习和面试定位重写规则。

修正属于完整执行和审读过程，6/6 是最终产物结论，不代表首次生成零问题。

### 验证边界

本次验证的是 Skill 的规则、生成正文与交付结构。DeerFlow 源码只读，最终工作区仍干净；没有启动 DeerFlow、真实模型应用链路、容器或执行其应用测试套件。27 项单元测试与六个生成行为用例分开计数，后者需要独立执行和内容审读，不能由 `npm test` 自动证明。
