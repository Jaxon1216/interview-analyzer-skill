# STAR、追问与口播要求

## 口播版（面经中的答题正文）

- **第一人称**：面经文档里「主问题 / 追问」的**口播正文**一律用「我」作主语（协作题可一句内用「我们」说明边界）。
- **字数**：每一道**主问题**、每一道**追问**的口播版均 **≥150 个汉字**（或等价符号不计入时以汉字为主），且须能单独讲清**完整 STAR**（情境—任务—行动—结果），禁止只列关键词。
- **结构**：推荐「场景（现象）→ 归因（根因）→ 动作（分层方案）→ 结果/兜底/待测」；详见 [口播与简历抽象](oral-and-resume-patterns.md)。
- **术语**：关键 API、库名、协议可加英文括号，如：`JSON.parse`、`safeParse`。口播里的私有函数名仍受 SKILL 密度预算约束。
- **待测数据**：口播中涉及性能、错误率等若暂无实测，用 **（待测）** 标出；测量思路写在导学文末「量化与验证」（见 SKILL 输出契约）。

## STAR 四要素（口播内需隐含或显式点到）

- **S**：业务与现场约束（上线初期、某环境、流量特征）。
- **T**：你的目标与可验证标准（哪怕定性）。
- **A**：你具体落地的步骤与权衡（为何不用更简单的做法）。
- **R**：结果、指标或（待测）+ 后续观测/降级。

## 出题顺序（禁止颠倒）

1. 已写完项目简介与 4～6 条一级简历 bullet（可嵌套）。
2. 填「简历 → 面试展开」表：每条一级 bullet 对应 1 道主问。
3. 再写口播。禁止先按仓库目录 / 测试文件巡检出题，再倒挤 bullet。

## 主问题设计

- **默认来源**：该条简历支柱里最硬的权衡或失败模式（面试官只看 bullet 就会问的那个）。
- 题干必须是**简历可读**的通用问题，见 [口播与简历抽象 · 出题契约](oral-and-resume-patterns.md)。
- 禁止题干出现：文件路径、私有函数名、issue 号、只有读过代码才知道的开关 / 枚举 / 内部字段。
- 正例形态：「为什么用这种结构，而不是把逻辑写在主路径里？」
- 反例形态：「某个内部配置键 / 函数为什么必须是这个字面量？」（像读过仓库）
- 题干正反例见 [oral-style-samples.md](oral-style-samples.md)（与该文件已有的 SSR 样例对齐）；完整契约见 [oral-and-resume-patterns.md](oral-and-resume-patterns.md)。

## 数量（只统计主问，追问不计入）

- **必出**：每个一级简历 bullet → **1 主问 + 2 追问**（约 4～6 道主问）。
- **可加**：2～4 道**简介级通用题**（该领域的基础权衡：一致性、隔离、降级、评估方法）。必须能从简介或 bullet 找到钩子，不要为凑数去扫鉴权样式、包体预算、点击时序等边角。
- **合计主问 8～12**。不要为凑数把导学里的实现细节逐条改成主问。

按主题分组时：建议 **一个一级 bullet 一个主题**；简介级通用题可单独成组或附在最相关支柱后面。

## 追问递进（每个主问固定 2 个）

1. **权衡与数字**：为什么是这个结构 / 这个阈值；不用更简单做法会怎样。
2. **失败与演化**：超时、降级、下游打满、回滚、重做会改什么。

追问仍然是面试官口吻，不要变成「那个内部函数为什么分两套」。实现细节放口播和源码证据索引。

## 频率标注

- 题目排序：**简历一级支柱（高）> 简介级通用题（中）> 不要为频率标签去发明边角题**。
- 标签 `通用` / `前端` / `后端` / `AI`。
