## 改造

统一规则位于[技术术语选择](../../skill/project-interview-skill/references/rules/oral-and-resume-patterns.md#技术术语选择)：先核对事实，再判断目标岗位同行是否熟悉，比较中英文后分别检查标题与正文，最后审读整句。英文有优势时直接保留；中文更自然时使用中文，不固定括号翻译、不设英文数量。公开可搜索的私有类名不自动成为通用概念。

Skill 入口、输出骨架、few-shot、提示词脚本、金样解构和私有名词规则同步引用这一标准。口播原有组织与私名预算未变。术语取舍留在生成者分析或评测说明，不进入简历正文。

首轮发现的译名问题支持一处窄修正：中英文名称及译名都须核对事实，不能增加未确认的执行载体、并发模型或保证范围；没有设置 worker 的永久译名或禁用“进程”。

- 两位独立执行子 agent 分别读取冻结的保存版和新版 Skill、相同原始请求与最少材料，不读取 `checks`、另一版输出或预期答案。每位执行者依次完成六例，每例第一次完整输出另存，术语理由单独记录。

- 修正规则后，新的独立执行者只得到冻结的修正版、同一 T6 请求与事实，以及补充 T7/T8 原始请求；不接收首轮结果、失败点或建议答案。原审读者随后检查这三份新输出，未覆盖首轮记录。
- 冻结包、输入、输出、执行说明、审读包与自动日志归档到本机 `.test-runs/technical-terminology-2026-10-13/`，该目录继续忽略提交。可移植正文和说明保存在下面的 samples；版本、材料、产物 SHA256 见 [manifest](2026-10-13-terminology-manifest.json)。最终运行时包与复测冻结包指纹一致。

## DeerFlow 五条逐条对照

以下“保存版”为保存点首轮原文，“新版”为修正规则后的新执行结果。相同事实与目标岗位：AI Agent 后端研发；没有个人职责、历史升级或收益数字，不从截图移植素材。首轮新版仍保留在上面的样本链接中。

### 运行与事件订阅

保存版：

- **异步运行与 SSE 恢复：** 网关受理独立运行并交由后台执行器处理，客户端通过 SSE 分别消费消息、状态更新和自定义事件；首次创建 POST 不自动重试，恢复既有运行使用 GET，回放出现缺口时重载持久状态。

新版复测：

- **独立运行与 SSE 事件订阅：** 服务受理独立运行并交由后台执行，SSE 连接按运行订阅消息、状态更新与自定义事件；初次创建不自动重试，恢复时连接已有运行，回放出现缺口则重载持久状态以恢复当前视图。

### 执行中间件

保存版：

- **Middleware 执行约束：** 通过有序 Middleware 组装模型与工具输入净化、工具输出预算、授权和错误规范化；工具可通过 LangGraph Command 返回会话状态更新，由对应 reducer 合并。

新版复测：

- **有序执行中间件：** 将模型与工具的输入净化、工具输出预算、授权和错误规范化按顺序组装为中间件，在调用链上落实执行约束；需要更新会话状态的工具返回 LangGraph 的 Command，由对应归并规则合并状态更新。

### 沙箱持有与释放

保存版：

- **沙箱持有与权限校验：** 按用户和线程身份获取或复用沙箱，执行前重新核验权限与归属；最后一个执行持有者退出后，由环境提供方释放共享环境，避免仍有执行者使用时提前释放。

新版复测：

- **沙箱持有管理：** 按用户和线程身份获取或复用沙箱，执行前重新检查权限与归属；最后一个执行持有者退出后由环境提供方释放沙箱，使释放时机与执行持有状态关联。

### 技能加载与工具授权

保存版：

- **Skill 按需加载与工具授权：** 将技能封装为包含 SKILL.md 的目录包，默认系统提示提供技能元数据，正文由显式选择或读文件工具按需加载；以轻量引用记录已加载技能，并将活跃技能的工具白名单同时落实到模型可见工具与实际调用。

新版复测：

- **技能按需加载与工具授权：** 将技能封装为包含 SKILL.md 的目录包，默认在系统提示中提供元数据，正文通过显式选择或文件读取工具按需加载；以轻量引用保留已加载技能，活跃技能的工具权限声明在模型可见工具列表与实际调用两处生效。

### 文件产物交付

保存版：

- **文件产物交付：** 将线程输出文件登记为规范产物引用，列表按增量合并并去重；通过经授权的文件接口读取正式内容，文本默认按字节预算请求预览，运行结束后刷新内容。

新版复测：

- **文件产物登记与受权读取：** 将线程输出文件登记为规范产物引用，产物列表增量合并并去重；正式内容通过授权文件接口读取，文本默认按字节预算请求预览，运行结束后刷新内容，将产物登记与文件内容获取分开。

## 术语取舍说明

| 术语或表达 | 本次取舍与理由 |
| --- | --- |
| React、SSR、HTML、hydrateRoot（T1） | 均有明确材料支持；面向 React 前端岗位，框架、渲染缩写、格式和公开入口有识别价值。仅写“页面接管”会丢失具体实现。 |
| Hydration / 水合（T1） | 保存版使用 Hydration，新版使用“水合”，正文均解释接管已有 HTML。两种表达均通过；不强制复制某一个英文。 |
| 幂等（T2） | 业务唯一编号与重复结果复用支持幂等；后端语境中文清楚自然，无需换成 Idempotency。两版均为零英文并通过。 |
| RAG（T3） | 已有索引、检索、增强模型输入和生成机制；AI 应用后端岗位的领域缩写紧凑且有辨识价值。向量索引、引用等说明继续用中文。 |
| SSE（T6） | 已核验的事件订阅协议，缩写比展开中文紧凑；正文保留消息、状态与自定义事件及缺口恢复的边界。 |
| LangGraph、Command（T6） | 明确的框架与公开 API；直接命名可定位状态更新机制，普通“命令”容易混淆。并用中文解释归并动作。 |
| SKILL.md（T6） | 已核验技能目录的固定文件约定，中文“说明文件”会丢失结构信息；不是源码路径或私有类名。 |
| POST / GET（T6 首轮） | 标准 HTTP 方法，有事实支持且可精确说明创建/恢复差异。复测以行为概括，仍保留边界；无需为了英文数量保留所有方法名。 |
| Skill / 技能（T6） | 首轮说明将 Skill 联系到目录包生态与 SKILL.md，允许保留；复测用“技能”也能概括按需加载与授权，不强制英文。 |
| reducer / 状态归并规则（T6） | 保存版保留框架状态合并角色名可接受；新版用中文解释合并动作，同样准确。没有把所有术语一律泛化。 |
| 中间件、沙箱持有、工具权限声明、文件产物（T6） | 中文能直接解释顺序、释放条件、双处授权与交付动作；当前句子无须改为 Middleware Chain、Sandbox、allowed-tools 或 Artifact。 |
| worker / 后台执行（T6/T7） | 原始角色不能证明进程或线程。“后台执行”保留已知行为，避免译名增加执行模型。 |
| CPU、multiprocessing.Queue（T8） | 计算类型及标准库进程间通信 API 有明确材料支持；对 Python 后端读者直接、精确，正文说明任务传递与结果收集。 |
| OmniExecutionFabric、finalizeOwnedRunX、execution_owner_key（T4） | 公开可搜索仍是项目私有符号；用共享客户端生命周期与最后使用者释放条件说明机制，不拿私名当架构标题。 |
| RAG、Agent Harness、Context Engineering（T5） | 只有固定提示词和模型调用，不具备这些概念所需机制；没有进入正文。T3 使用 RAG 不意味着所有 AI 项目均适用。 |

逐词理由是本次评测交付材料，未追加到生成的简历 bullet。以上熟悉度与表达优势为结合目标岗位的语义审读结论，未声称统计过同行使用率。
