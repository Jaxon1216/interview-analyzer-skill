# 按需 HTML 教学深化

适配自 Matt Pocock 的 [teach](https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/productivity/teach/SKILL.md)。吸收目标驱动、小范围讲透、可信来源、文件承载上下文以及“生成不等于学会”；来源与 MIT 许可见[上游记录](../upstream/sources.md)。这是当前 Skill 的模式，无需安装或调用另一个 `/teach`。上游没有随附可直接复制的 HTML 模板或模拟器。

## 进入与范围

用户明确要求 HTML、交互教学或使用文末提示词时进入；普通概念追问直接回答。此模式可从已有 Markdown 开始，不要求重新提交项目描述、重跑整套简历与课程，也不要求旧文档先补齐新模板。

先读选中课程/文档、相关导学目标、必要的面经 B/Q/C 与源码落点，检查已有 HTML 入口、用户笔记和本次难点。C/Q 编号需连同项目、方向和路径定位；多个候选且无法消歧时集中询问。目标已经清楚时直接做，不启动 Mission 访谈。

默认处理用户选定的一课；指定小节时只展开该小节及理解它所需的前置解释。已有课程很长时可在一个页面内按一条条因果链组织，不擅自删掉请求范围。面经按 Q 编号/小节深化，复用相关课程；不默认转换整份面经。自由主题先定位相关课程或源码，未实现内容标为通用原理/进阶方案。

## 查证与教学组织

1. 区分原文基线与本页实际查证基线。记录项目、来源 Markdown、C/Q、完整小节层级、源码 commit 和必要的工作区变动；无 Git 如实说明。旧课与源码不同，只查影响本节的链路，写清采用哪一版和具体差异，不声称整套材料已更新。
2. 来源优先使用项目源码/测试及对应版本的官方资料。API 或版本不确定时查官方文档；课内链接到支持主张的具体位置，不伪造引用。源码不可访问时可基于现有文档讲解，注明未重新核验，不猜文件名、符号或测试结果。
3. 从一个输入或用户操作讲起，先给关键结论，再展示调用顺序、状态/数据归属、关键代码与正常/异常分支。说明每一步为什么发生，回到用户不理解的地方；不要仅把 Markdown 排成网页。
4. 按机制选择有解释作用的交互：切换正常/失败路径、逐步看状态、对照输入输出、给代码加关联注释。核心解释和答案默认可读；补充细节可以折叠，不能用答题或预测解锁正文。
5. 结尾保留必要的必懂因果、必记流程和相关面试题入口。推荐最有帮助的主要来源，并说明可以继续追问哪个具体难点，不用“继续问 AI”代替讲解。

引用短代码时保留必要上下文并转义 HTML；伪代码、状态模型、模拟结果与真实实现分清。模拟器展示因果，不冒充项目运行、性能测量或已执行测试。没有源码支持的退避、幂等、并发或持久化不能为了交互完整而补造。

默认不加入测验、练习、预测、实验命令、社区推荐或间隔复习。用户明确要求时再提供，并说明前提和结果边界。不自动创建 `MISSION.md`、学习档案、术语掌握记录；已有用户偏好可以读取，不能根据生成/打开/阅读页面自动记录“已掌握”。

## 输出位置、身份与更新

- 默认在来源 Markdown 所在目录的 `html/` 输出。整课用来源文件名改为 `.html`；小节用“来源文件名--小节名.html”。中文可保留，移除 `/\\:*?\"<>|` 等跨平台非法字符，避免尾随点/空格、空名称和保留设备名。
- 身份由来源文档的项目根相对路径、C/Q 编号与完整小节层级组成，写进 HTML 元数据注释。页面显眼位置标明可读的来源、范围、原文基线和本页查证基线。
- 先查原文已登记入口并核对目标页的来源/范围，命中则沿用路径，不因标题改名另建重复页。无登记或同名文件属于别的范围时，以来源与范围的短稳定哈希后缀消歧；不能覆盖不明文件。
- 重复请求只改当前范围。保留原 Markdown、其他课程、已有 C/B/Q 与用户笔记。HTML 也可能被用户修改：只更新可辨认的生成区，保留用户区；无法可靠分离时保留旧页，另存新版本并说明，不整页覆盖。
- HTML 不回灌为 Markdown 的事实依据；有内容修正时说明差异，按用户请求更新，不偷偷把旧课全部改写。

首个页面可用如下区域标记，便于后续保留笔记：

```html
<!-- project-interview-html: 在此写入本页真实来源、C/Q、范围与两份基线 -->
<!-- generated-content:start -->
<!-- 此区域为生成的教学内容 -->
<!-- generated-content:end -->
<!-- user-notes:start -->
<!-- 用户在此区域维护笔记；重复生成时原样保留 -->
<!-- user-notes:end -->
```

首次成稿填写真实元数据与教学正文，不把上述示意注释当作交付内容。区域内若发现用户修改也应保留；标记不是随意覆盖已编辑内容的许可。

## 页面要求

生成一个无需构建、可离线打开的完整 HTML 文件，内联 CSS/JS，默认无 CDN、远程字体、`fetch` 或运行时依赖。已有页面可学习排版与交互风格，但不要在这次请求中引入共享资源依赖；以后确有复用需求再另行设计。正文无 JavaScript 也能阅读，交互只增强讲解。

设置中文 `lang`、UTF-8、viewport、清晰标题与分级标题。正文宽度与字号适合阅读，窄屏不裁掉内容，长代码可局部滚动；打印保留关键解释。使用语义按钮、可见焦点、键盘操作与恰当的状态提示，动画遵从减少动态效果设置。图示配文字说明，不能只靠颜色区分状态。

页面包含必要源码片段与解释，独立发送文件也能读懂；返回 Markdown、相关课程/面经及本地源码使用正确相对路径，保留目录结构时可导航。计算链接时沿用课程规则的真实路径解析；空格等字符做 URL 编码或正确转义。代码作为文本显示，不能通过 `innerHTML` 执行源码或用户内容。

## 生成成功后的登记

在来源 Markdown 尾部的 `## 按需生成 HTML 讲解` 区域保留原提示词，增加或更新一条 `范围 → HTML 文件链接 → 本页查证基线`。只有页面实际写入并完成可执行检查后才添加链接，重复请求不重复登记。若检查受环境限制，链接旁注明具体未验证项，不宣称全部通过。

HTML 链接不能加入“简历 → 面试展开”的核心课程列或 Q 元信息“学习入口”；这些字段仍指向索引中的 Markdown 课程。没有生成的页面只写预期路径文本，不提前创建空文件或死链接。浏览器按钮不承诺能自动调用用户的本地 Agent。

## 检查与交付

先检查文件可读取、本地 `href/src` 的目标存在、页内锚点可解析、没有外部运行依赖和未转义源码。核对范围、两个基线、来源、解释因果与 B/Q/C；确认没有新增项目机制或删除笔记。

能用浏览器时以 `file://` 离线打开，检查桌面和窄屏、每类控件及正常/失败分支、键盘操作、控制台错误、网络请求和返回链接。浏览器不支持本地文件时可用本地静态服务查看排版和交互，但单独注明尚未实测 `file://`；不能把服务端预览当作离线验证。工具不可用就报告具体未验证项，不声称已打开或全部通过。

现有 `validate_output.py` 只校验 Markdown 结构和文件链接存在，不解析 HTML、不执行 JavaScript。保留 Markdown 的结构校验，并单独报告上述页面检查。交付实际 HTML 路径与来源 Markdown 的入口位置，说明任何尚未验证的部分。
