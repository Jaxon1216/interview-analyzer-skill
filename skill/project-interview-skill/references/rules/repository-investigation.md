# 仓库探索与机制归档

探索用于识别值得学、值得讲的项目机制。默认目标简历模式不审核个人贡献，不主动检查 commit author；用户提供的参与经历可用于同等含金量下的排序。仅用户明确要求实际贡献材料时，按其说明限制范围。

## 范围与入口

- 确认项目根目录、语言、框架、入口、配置和部署方式，区分业务源码、生成代码、依赖、示例与测试。
- README 用于理解目标，源码用于确认行为；不要仅凭目录名或文档宣传抽取支柱。
- 默认全栈覆盖仓库中实际存在的前后端，不意味着各占一半；无前端源码时只讲调用端契约。
- 记录当前源码基线或分析日期与模块范围，帮助日后更新课程；无需统计作者或寻找个人改动证明。

## 沿场景追踪

先用几句话梳理 `服务对象/场景 → 项目目标 → 关键障碍 → 可观察的结果维度`，标出材料来源。业务目标也可以是开发者接入、交付效率、数据正确性等工程目标，不强行改写成营收或增长。材料没有说明的历史痛点不补造；从当前机制推导的设计目的标为分析，不声称是团队当时制定的 OKR。目标不明时先按已知能力组织，不让补充业务材料成为默认生成门槛。

先追踪 2～4 条代表性链路，再按支柱和课程需要补查。包括启动与依赖绑定、请求/事件入口、数据与状态变化、异步消费或回调、对外结果及资源清理。异步目标要追到注册、投递与消费位置，不能仅因函数名相似就认定调用关系。

每条链路回答：

1. **问题与目标**：谁在什么场景下受影响，当前机制解决什么矛盾，保护哪个业务状态或推进哪个目标？没有演进证据时直接解释当前问题，不虚构旧架构或事故。
2. **机制**：输入输出、关键状态、模块职责与实际调用顺序是什么？
3. **边界**：哪里会超时、竞态、不一致、重复执行或资源泄漏？实现了哪些处理，还有哪些限制？
4. **效果与验证**：实现、测试、配置和运行结果分别能证明什么？代码可见的结构效果与性能实测分开。

候选支柱事实卡：`服务对象/目标 | 问题 | 已实现机制 | 约束/失败边界 | 具体效果/结果维度 | 实现与结果来源 | 验证状态 | 历史决策依据（可空） | 进阶方案 | 用户明确参与（可空）`。事实卡用于分析，不照搬成简历字段或给每条 bullet 加证据尾注。

## 证据与结果边界

- **实现证据**说明机制做了什么：源码、配置和测试代码不能单独证明已经上线、测试已通过或产生业务收益。
- **责任证据**说明本人负责什么：贡献模式使用用户陈述、任务分工或 PR 等明确范围；用户陈述注明来源，与其他材料冲突时集中核实。默认目标模式不以此过滤机制，也不检查提交作者。
- **结果证据**说明变化是否发生：区分代码可见效果、已执行测试/验收、压测结果和线上指标。监控、报告或用户陈述保留来源与归属；团队同期结果不能自动归因于个人改动。

有指标时记录 `名称 | 基线→结果 | 单位/统计对象 | 时间窗口 | 环境与负载 | 来源 | 团队/个人归属 | 归因依据`；缺失项明确未知，不补猜。比较前后值须口径可比，不混用均值与 P95、压测与生产或不同负载；成功率变化区分百分点和相对百分比。不同口径的数据可以分别保留，不能直接计算改善幅度。工程延迟下降不能直接推出转化增长。

只有当前实现时写运行机制及其可支持的效果；只有设计目的时用目的语气，不写成已验证收益。无指标也可写具体能力，不要求新造实验。指标缺口放证据索引或相关回答，测量计划不进入已完成成果。

历史决策、方案演进需要当时的文档、PR、版本差异或明确的用户陈述支持；当前代码不能证明过去比较过哪些方案。事后替代方案用“现在回看/如果重新设计”表述，并行组件不包装成阶段一/阶段二。目标模式的第一人称可以讲解实现，但不能补造“我当时评估、推动上线”等经历。

## 选材与课程落点

结合目标相关性与技术深度，优先能解释动机、替代方案、失败处理和验证方法的机制。每个候选回答“它解决哪一步障碍、哪个行为或状态会改变、证据在哪里”；同一问题下的零碎功能合并成支柱，无关亮点可放选读或其他项目。架构、跨模块约束与系统机制优先于单点工单；近期修复可以作为其下的实现案例，不应挤掉项目核心能力。简历主线的聚焦不缩减必要的核心课程覆盖。

仓库已有但用户尚未学会的机制可以进入目标 bullet，必须配套核心课程。未实现增强列作进阶目标，不因理想方案更完整就把它混入现状。找到 bug 时准确说明影响，在对应课讲清影响与正确做法；仅用户要求时设计修复实验；不把整个面经改成代码审计报告，也不自动修改业务代码。

只有用户描述时注明资料范围，路径、符号、实验结果无法核验就说明缺口。缺少指标时用具体机制效果，不反复追问线上数据后才出稿。真正影响选材的问题集中询问，其他内容先完成。

每条支柱已有目标、机制、失败边界与可定位证据，且继续读取只会重复这些信息时，停止扩展该支柱；仍需查清会影响主张真假的依赖，并完成其余核心课程的必要查证。
