# Bullet 选材与成稿评测

本组为独立生成与人工语义审读用例，不由 `npm test` 调用大模型。旧术语评测保持原样；本组不预先裁剪 DeerFlow 的事实或指定支柱、条数和用词。

- `deerflow-request.md`：真实本机仓库的完整分析范围，源码只读、按需查证，仅生成简介与 bullet。
- `edgemetric-request.md`：不同领域的简短合成材料，事实未按支柱分组；没有源码、指标或个人经历。

生成者仅获得冻结 Skill（含其原有引用）、仓库或原始材料与请求，不获得下面的审读标准、旧输出、预期答案或本轮诊断。保存第一次完整输出；后续修订另存，注明规则是否变化、是重新生成还是编辑修订。

分别记录以下判定，不合并成一个“通过”：

| 维度 | 审读问题 |
| --- | --- |
| 整组选材 | 能解释项目主要任务怎样完成吗？核心职责与系统机制是否进入主稿？材料分组、接口或权限检查是否取代了核心机制？ |
| 标题辨识度 | 目标领域同行能否识别具体设计？名称是否被正文的实际机制支持？接受准确同义表达，不要求金样标题。 |
| 运行机制 | 能否读懂谁负责什么、如何协作、哪个条件改变行为？关键实现是否保留，而非只剩架构大词或源码动作清单？ |
| 约束与作用 | 边界是否精确？作用是否由机制支持？是否重复条件、使用空泛尾句或强行补收益？ |
| 事实 | 源码或材料是否支持所有主张？有无借用金样身份、历史、层数、数字或技术组合？ |
| 术语（单独） | 名称准确、目标领域熟悉，中英文选择自然且有辨识价值；存在中文译法不构成删除英文的理由。 |
| 可追问性 | 主问能否从成稿自然引出设计动机、运行机制、取舍或边界？无需输出完整面经。 |

成稿判定包括整组选材与逐条语言；术语合格不能抵消前者缺陷。单次生成仅说明本次行为，不能证明稳定优于旧版。内容审读与自动结构回归分开报告。
